# GEN-UI · 产品架构全景板（按需）

当用户明确要求**产品架构图、产品架构全景、分层能力地图**，尤其提供了“顶端渠道入口、横向能力分层、左右贯穿支撑体系”的参考图时，优先采用这种结构，而不是把产品架构简单画成四个孤立的卡片。此规则是 [八类架构图表达契约](architecture-patterns.md) 的一种**产品架构版式**，不是第九类架构，也不改变普通回答默认 Markdown 的规则。

## 画面组织（由内容决定，不能生搬硬套）

```text
                        产品架构全景图
    PC 门户 / 运营后台 / 数据大屏 / App 等真实入口
                         统一入口（可选）
基础支撑 ┃ 应用展示层：业务工作台、运营视图、报表 ┃ 治理保障
        ┃ 中台能力层：数据中台       业务中台 ┃
        ┃ 业务后台层：采购、销售、仓储、财务等 ┃
        ┃ 分析建模层：指标及业务分析能力     ┃
        ┃ 标准层：业务模型、指标口径、字典等 ┃
        ┃ 数据整合层：可信来源、同步、存储   ┃
```

1. **先盘点事实**：从用户资料抽取真实的渠道、层、模块、系统边界、数据来源、已知关系和证据；仅展示已有内容。上图的“数据中台”“统一入口”等是可选例子，原文没有则不得凭审美添加。
2. **用横向层带表达包含关系**：同层模块排列为网格；中台等复杂层可分成 2～3 个内部容器；层级名称固定在左侧。把横向和纵向间距留足，避免用细小文字换取“信息量”。
3. **左右贯穿侧栏只承载横切能力**：鉴权、安全、监控、风控、运营治理等可以成为支撑体系，但必须具有真实范围；不把具体业务模块重复放入侧栏。
4. **箭头是关系，不是装饰**：只在有来源支持的接口、数据流、控制或依赖关系上画箭头，写清方向和语义。纯包含关系用边框和分层，不自动给每层加“调用链”。演示可标“示例关系”，不能暗示生产已验证。
5. **区分来源状态**：已实现、规划中、示例、待验证必须在标题/图例/模块文字中说明。产品架构不等于系统部署图；没有证据不画生产调用、服务实例或真实数据血缘。
6. **交付轻量化**：简单回答仍用 Markdown；明确需要图形文件时优先提供**静态离线 HTML/SVG**，不为了全景板引入新 JS 框架或第三方 CDN。桌面默认宽画布；窄屏在图内滚动，不允许整页水平溢出；打印优先横向。
7. **图外仍可阅读**：图前提供一句话总览，图后保留同一层级的文字版和关键边界；浅色层带与深色文字保持对比，不能以颜色代替文字。图中文本可选中，不要用整张位图承载唯一信息。

## 与 GEN-UI SVG 系列统一的视觉风格

架构结构可以借鉴宽幅分层海报，**视觉样式必须沿用现有 SVG 系列**：白底/浅灰点阵画布、`#3A83F7` 蓝色强调、`#344054` 深色文字和小圆角。不同能力层使用**清楚可区分的浅蓝、薄荷绿、浅紫、暖琥珀和浅青色整块背景**；层标签、内容容器与模块卡片使用同一色系的不同明度，同时保留文字名称，不靠颜色单独编码业务含义。每个标签、模块、入口都用**四边等粗的细边框**，**不允许左侧加粗或高亮竖线**。禁止大面积高饱和底色和粗边框，箭头只表示有来源的关系。复用 [本地 SVG 主题 CSS](../assets/product-panorama-svg-theme.css)，但不能以配色为理由改变业务层次或编造链路。

## 最小可复用示例

[离线产品架构全景板](../demo/product-architecture-panorama.html) 是**纯 HTML + CSS** 示例，无脚本、无远程资源，采用顶部渠道、统一入口、六层能力地图、左右支撑侧栏与底部数据存储。里面的商贸产品模块是虚构演示，不是项目扫描结果；实际生成时应**替换模块和关系**，而不是套用这些业务名称。

**验收**：来源模块名无遗漏或无中生有；宽屏层带和分组可辨认；375px 窄屏仅在图容器中横向滚动；无 JS 时仍有完整文字内容；箭头无虚构语义；实际浏览器/打印检查与静态结构检查分别记录，不互相替代。
