# GEN-UI · 静态 HTML 报告要点（按需）

> 只用于用户明确需要**离线 HTML/网页报告**，且内容主要是静态章节、表格和结论的场景。普通问答仍用 Markdown。复杂交互、单文件打包、专业语义图、门户/多页面导航等，转用 [完整 HTML 合约](html-report-contract.md)，不得删减用户已要求的功能。

## 一、先保证内容

1. **事实优先：** 结论在前，后接依据、限制、风险和待办；用户提供的数量、版本、条件保持准确。设计建议用「建议/待明确」，未实际验证用「待验证」，不得把它们写成已上线或已通过。
2. **章节清晰：** `html lang="zh-CN"`，一个 H1；H2/H3 组织目录，H4 为正文。中文标题统一采用「一、二……」「（一）（二）……」，不得与小数层级混排。
3. **按需表达：** 方案比较用表格，步骤用有序列表；只有真实数据和读者问题需要时才引入图表。静态报告不添加无实际功能的筛选器、复制按钮、弹窗或数据仪表盘。

## 二、离线与阅读要求

- **真实左侧导航：** 保留可见的 `<aside class="doc-toc">`、`<nav>`、`<ul class="toc-list">` 和指向 `<main>` 内真实 ID 的锚点。即使 JavaScript 失效，也必须能点击静态目录。按现有项目契约引入**本地** `heading-nav.js`，不要凭空引用不存在的资源。
- **样式：** 背景 `#FFFFFF`、正文 `#1A1C1F`、强调 `#3A83F7`，正文 14px、代码 12px、系统字体。移动端不出现整页横向溢出；宽表格单独可横向滚动。
- **资源：** CSS/JS/SVG 使用本地相对路径并核对资源存在；不依赖 CDN、远程字体或在线图片。引用外部公开资料时，放在文末参考资料中，不将其当作运行依赖。
- **交互与可访问性：** 链接、导航和必要的折叠控件可用键盘访问；有图标按钮时必须有可读名称。无需交互的报告就不要制造可点击假按钮。
- **元数据：** 报告生成时间据实记录到秒，页面可见时间不附带生硬的时区后缀，机器可读属性可以保留时区；使用项目中实际存在的本地 GEN-UI SVG favicon，不伪造路径或图片。

## 三、交付与边界

静态正文优先成形，再加入样式与导航；不为装饰增加章节、空数据或伪造进度。不使用不可信的模型生成代码直接操作外部系统，不向用户保证未执行的动作已经成功。

本模式面向**仓库内可引用本地资源**的静态页面；如果用户要求真正独立的单文件、自定义交互或复杂可视化，则切换完整合约，而不是把完整功能压缩成一个不可用的空壳。

正常交付时遵循项目的 `node scripts/validate-html-report.mjs <report.html>` 规范；**用户明确要求跳过测试时不执行**，交付说明如实标注「未测试」。
