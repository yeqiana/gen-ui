# GEN-UI · 八类架构图表达契约

仅在需要架构呈现时加载。架构图不是一律「色块＋连接线」。数据没有可信关系就只呈现容器及层级。

| 类型 | 推荐的无连线布局 | 存在什么信息时才画连接线 |
| --- | --- | --- |
| 业务架构 | 业务域容器、业务能力和价值链分层 | 跨域业务流 |
| 产品架构 | 产品线、产品族与模块分组 | 产品依赖 |
| 系统架构 | 系统边界、子系统的分层大框 | 系统集成、通信 |
| 数据架构 | 来源、治理、存储、消费层堆叠 | 血缘、流向、同步 |
| 技术架构 | 接入、服务、技术组件与基础设施层 | 技术协议与接口 |
| 应用架构 | 应用群和服务边界大框 | 应用服务调用 |
| 功能架构 | 功能分解树、能力分组 | 功能编排顺序 |
| 信息架构 | 栏目、导航、分类树 | 页面跳转旅程 |

## 绘制准则

1. 先判定表达的是 **包含、分层、分类**，还是 **依赖、顺序、流向**。
2. 包含关系优先画嵌套大框，层次用纵向堆叠，同级功能按网格排列。使用边框、留白、浅背景区分归属。
3. 关系信息明确才选七类专业图或带箭头的依赖图；不为填满画布虚构连线。
4. 每个层级保留标题及实际实体名称；不会因美化创造服务、接口或架构层。
5. 图表可选本地增强，普通 Markdown 不依赖任何 JS。HTML 的离线架构容器示例见 demo/architecture-patterns.html。
6. 缩放、全屏、折叠、键盘控制按需支持，操作按钮统一图标、中文说明；真实 Chrome 验收和单元测试分别报告。

## 真实工程案例与模型契约

- 八类示例位于 demo/architecture-patterns.html，使用本地 Yopu（Gateway、CRM、Trade、Billing、IM）、StoryOS（Workflow/Task/Attempt、Agent、Trace/Artifact）工程模块和架构资料整理；展示的是逻辑协作，不代表所有服务已部署或通过运行验收。
- 离线架构 JSON 支持可选 flows[]，元素包含 from、to、label，可附 basis（design/implementation）、evidence（仓库相对文档路径）。标记 basis=implementation 时必须提供非空 evidence；design 关系也应尽量给出来源。引用可使用顶层 groups[].name 或稳定 groups[].id。顶层名称与 ID 不能重复或交叉歧义，禁止自身关联、悬空引用。无可信关系则省略 flows，仅展示容器。
- 模型输入上限：最多 3 层嵌套、128 个分组节点、512 个项目节点、12 条关系，序列化 JSON 不超过 64 KiB；超限必须拒绝渲染。
- 八个真实示例的 24 条关系均按 **设计依据** 标注来源，不能因某个服务目录存在就声称调用链已在生产环境验证。每条关系应可追溯到具体文档或实现证据。
- 关系箭头通过独立 SVG 覆盖层锚定至对应顶层容器的可见边界；容器与箭头处于同一缩放画布，折叠后重排。桌面、移动和全屏使用统一布局机制，禁止容器缩放、关系线不缩放的错位状态。相同起点与终点的多条关系合并为一条共享连线，但每条关系标签与证据必须逐条保留；正向与逆向关系分别使用两侧轨道，标签卡片明确显示「起点 → 终点」，避免反向箭头和同端点重复连线相互遮挡。每侧轨道按端点位置稳定排序，容器边缘为多条入/出关系分配分离端口，箭头不得穿过关系标签；容器尺寸变化由 ResizeObserver 触发布局更新，销毁实例时必须断开观察器并移除全局监听。
- 每个方向连线由两个明确的容器端点、真实关系标签、可辨认的小尺寸箭头构成；标签文字决定连接线所需宽度，箭头尺寸固定，不因标签长而放大。移动端允许图内水平滚动，不允许页面整体横向溢出。 无 JavaScript 时，HTML noscript 摘要仍须包含分组/节点和显式关系文字，不能只留空白画布。
- 可加载的目录图标在展开态默认隐藏，折叠后保留；数据对比表仅文字着色，绝不消除表格原有的边框、间距和斑马纹。
- 本地例子不包含私有地址、端口、密钥或运营数据；涉及设计文档的部分请读者与运行代码区分。禁止基于未核实的设计推断实际生产部署。
