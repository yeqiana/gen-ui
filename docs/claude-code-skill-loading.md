# Claude Code 中触发 GEN-UI：最小权限指引

GEN-UI 以 Markdown 为默认输出。普通提问可以自动发现 Skill；需要确定使用时，直接以 `/gen-ui` 开头。**两者都不等于模型每次都实际读取了参考文件**，应按工具记录区分 Skill 调用、规则读取成功与读取被拒绝。

## Windows（PowerShell）

若已经通过 `~/.claude/skills/gen-ui` 安装 Skill，而模型尝试读取用户级规则时提示需要权限，可仅允许读取 GEN-UI 的**安装目录**：

```powershell
claude --setting-sources user,project --add-dir "$HOME\.claude\skills\gen-ui" -p "/gen-ui 请续接这一轮评审，区分已实现、已验收和未决风险。"
```

仅在明确认可授权范围时使用该命令。不要授权整个用户主目录、所有 Skill 或 Git/Token 目录；不要把密钥放入提示词。工作区本身已安装的 Skill 可以优先使用项目内文件，不需要为了绕过权限而复制私密文件。

## 本次证据边界（2026-11-16）

- 同一桌面账号中有多种 Skills。初始统计误将其他 Skill 的调用计入 GEN-UI，因此只能按实际 `input.skill === "gen-ui"` 统计 GEN-UI 工具调用。
- 在冻结的 32 次自然/显式对照中，16 次显式 `/gen-ui` 调用均进入模型会话，但只观察到 5 次**成功读取 GEN-UI 规则文件**，自然语言则为 1 次；显式组发生 7 次读取拒绝。客户端可能直接展开斜杠命令而不生成独立 Skill 工具调用，因此这里统计的是**可观测的文件加载**，不是完整的内部激活率。
- 使用上面的定向 `--add-dir`，对 3 个原先出现读取拒绝的样例重新运行：3/3 成功读取 GEN-UI 规则，未再发生读取拒绝。三次只说明**可解决这组权限问题**，不证明模型回答内容普遍提高。
- `--setting-sources project` 的完全项目隔离探针因缺少桌面账号认证而失败，随后改为 `user,project` 才可调用模型。因此自动发现实验有全局账号和设置的干扰，不应当作严格双盲研究。
