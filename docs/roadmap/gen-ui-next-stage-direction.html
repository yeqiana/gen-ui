AI INFORMATION DESIGN SKILL

GEN-UI 下一阶段方向

从“让 AI 生成更漂亮的界面”，转向“教 AI 理解信息、组织知识、选择表达形式，并交付高可读性内容”。

UI 是表达手段，信息理解才是目的。

方向指导 · 非功能排期生成时间：2026-11-12 10:10:18 UTC+08:00适用：Skill / References / Assets / Tests / Evals

方向结论

最高优先级 · PRODUCT BOUNDARY

GEN-UI 永远以 Skill 为唯一产品定位。

不盲目扩张产品边界，不为了功能丰富而增加功能，不把 Skill 发展成 UI 框架、组件库、独立工具平台或复杂运行时。

所有能力建设必须围绕一个目标：教会 AI 更好地理解信息、组织知识、选择表达形式并交付高质量内容。新能力优先通过更好的指导原则、决策规则和按需加载的参考资料解决；只有当 Skill 指导本身无法解决真实问题，且有充分证据证明必要时，才考虑增加实现资源。

本原则对所有后续功能、路线、技术选型和版本规划拥有最高优先级与否决权。与其冲突的提案不进入 GEN-UI 范围。

保持 Skill 产品形态，不转型为 UI 框架。 GEN-UI 的核心价值不是拥有多少组件，而是让 AI 在面对不同信息任务时，能够作出恰当的信息设计决策。

下一阶段的主线应从“继续增加表现能力”切换为“提升表达决策和输出质量”。保留现有 HTML、七类语义图和架构视图，但它们都应是按需使用的表达手段，而不是默认目标。

  • Markdown 默认，HTML 按需，复杂语义图按需。
  • 优先建设信息理解、知识组织、表达决策和质量自检。
  • 暂缓新增图表类型和复杂装饰组件。
  • 用真实 Agent 行为评估证明规则有效，而不只看静态规范或截图。

产品定位与边界

使命

让复杂信息更清晰，让重要知识更容易被理解，让有价值的内容更容易被使用。

GEN-UI 是什么

  • 指导 AI 进行信息理解、知识组织和表达决策的 Skill。
  • 按需加载的表达规范与实现资源。
  • 验证输出质量、规则遵循和跨 Agent 兼容性的测试体系。

GEN-UI 不是什么

  • 不是通用前端框架或 UI 组件库。
  • 不是把普通回答强制转换为 HTML 的渲染器。
  • 不是图表越多越好的可视化集合。
  • 不是事实核查、代码评审、测试或业务判断的替代品。
  • 不是绑定某个模型或 Coding Agent 的专有工作流。

五项核心能力

01

信息理解

识别任务目标、读者、上下文、约束和决策点，知道读者真正需要理解什么。

02

知识组织

提炼结论、证据、概念、因果、依赖、风险和行动，把零散信息组织成结构。

03

表达决策

判断文字、列表、表格、流程图、语义图或 HTML 是否必要。

04

信息呈现

控制层级、重点、布局、可读性和必要交互，降低阅读与理解成本。

05

质量自检

检查事实边界、完整性、可访问性、表达适配和安全回退能力。

端到端工作闭环

这是 AI 的内部工作方法，不是要求每个回答都输出六个固定章节。简单问题直接回答，复杂任务才逐步展开。

  1. 理解任务与读者需要理解、比较、决策、执行还是验收？
  2. 识别信息结构区分事实、输入、推断、建议、风险与待确认事项。
  3. 组织知识梳理结论、证据、原因、关系、步骤和行动。
  4. 选择表达形式选择足以解决理解问题的最简单形式。
  5. 生成内容内容准确优先，再使用视觉和交互手段。
  6. 质量自检检查遗漏、误用、复杂度和回退能力。

表达形式决策

信息特征 / 阅读任务首选表达使用边界
简单解释、结论、短建议Markdown 段落不为视觉效果增加容器
并列要点、操作步骤列表有顺序才使用有序列表
多方案、多指标比较表格控制列数，突出决策数据
明确的先后、分支、状态流转流程图 / 活动图关系能帮助理解时才画
多参与者调用与消息顺序时序图参与者、消息和顺序必须有依据
层级、归属、分类思维导图 / 分层结构归属关系不伪装成调用连线
系统边界、组件、部署与依赖架构视图 / 拓扑图只连接真实依赖
长篇、分章节、需要导航的文档离线 HTML明确请求或阅读场景确有价值时使用
复杂关系探索可交互语义图交互必须提升理解，不能只是装饰
决策顺序：先判断信息要解决什么理解问题，再选表达形式；不能先决定画图，再勉强寻找内容填充。

必须坚持的设计原则

Content First · 内容优先

事实、逻辑和完整性优先于视觉效果。

Reader First · 读者优先

围绕读者的理解任务组织内容，不围绕组件组织内容。

Right Representation · 恰当表达

只使用能降低理解成本的表达形式。

Minimalism · 最小复杂度

能用 Markdown 讲清楚，就不生成 HTML；能用表格讲清楚，就不强行画图。

Progressive Enhancement · 渐进增强

Markdown 是可靠基础，HTML 与交互按需加载；增强失败不能损坏主要内容。

Information Integrity · 信息真实

不得为了视觉简化而改变含义、遗漏限制或虚构证据。

Agent Agnostic · 跨 Agent

优先使用标准 Markdown、HTML、JSON、SVG 和可移植约定。

Graceful Fallback · 安全回退

宿主不支持交互时，仍交付可读文本或静态解释。

补充原则：Evidence Before Claims。示例、推断、计划和实际执行结果必须明确区分。

Skill 能力分层

层级加载策略内容边界
L1 · Core默认加载任务理解、知识组织、表达决策、Markdown 基础和质量原则
L2 · HTML明确需要 HTML 时加载页面层级、导航、布局、表格、代码、离线与可访问性规范
L3 · Visualization复杂关系确实需要时加载七类语义图、JSON 契约、SVG 引擎、交互与专项测试
QA · Evaluation开发、评审和验收时使用自动化测试、浏览器测试、Agent A/B 和案例库

仓库资源职责

  • SKILL.md：入口、意图识别、决策路由和最小验收要求。
  • references/：按需读取的详细原则、HTML 契约、图表模型和架构规则。
  • assets/：经过审查的 CSS、JavaScript、SVG 实现资源。
  • tests/：功能、边界、回归和离线能力验证。
  • evals/：不同 Agent 对 Skill 的理解和使用评估。
  • docs/：产品定位、设计决策、版本方向和开发说明。

不要把高级实现细节重新复制进核心 Skill，也不要因为资源默认不加载就删除成熟能力。

下一阶段建设路线

STAGE 0 · STABILIZE

完成当前版本稳定性收口

先让现有能力可靠，不把已知缺陷带入下一阶段。

  • 整合当前并行改动并完成评审
  • 修复桌面与移动端目录等回归
  • 验证语义图、架构视图和 HTML 离线行为
  • 保留可重复的压力与回归测试
STAGE 1 · DECISION

智能信息设计决策

下一阶段主线：让 AI 知道应该怎样表达，而不只是有哪些组件。

  • 新增轻量决策参考规则
  • 覆盖读者任务、复杂度、形式选择和反例
  • 测试 HTML / 图表误用与过度设计
  • 核心入口保持轻量
STAGE 2 · EVALUATION

真实 Agent 行为评估

证明轻量化没有损害能力，并验证新决策是否提升质量。

  • Markdown、HTML、Visualization 三类任务
  • 同模型、同任务的新旧 Skill 对照
  • 保留原始输出、参数、评分和失败原因
  • 额度不足或超时不计入通过
STAGE 3 · EXAMPLES

案例与交互能力增强

让用户看到理解成本的改善，而不是只看到页面更漂亮。

  • 项目分析、架构设计、实施、测试验收案例
  • 真实 Before / After
  • 探索节点详情、步骤浏览和正文联动
  • 只有确实提升理解的交互才保留

功能准入评审

任何新功能、规范或资源进入 GEN-UI 前，都必须回答以下问题：

  1. 它解决了哪一种真实的信息理解问题？
  2. 现有 Markdown、表格或图表为什么不够？
  3. 它会不会增加默认上下文、安装、运行或维护成本？
  4. 能否按需加载，并在不支持时安全回退？
  5. 是否跨 Agent、离线可用，且不依赖不可信脚本？
  6. 是否有独立测试证明收益，并覆盖回归风险？
准入规则：没有明确理解收益不做；只是视觉装饰不做或降级为可选；默认增加复杂度优先重设计加载路径；无法验证效果先做实验；已有能力足够就复用。

质量指标与验收方法

以下是建议建立的指标，不代表当前已经达到的成绩。先收集基线，再确定正式阈值。

维度观察指标验收方法
决策质量表达形式适配率、过度设计率固定任务集与人工评分
信息质量结论、依据、限制、行动完整度结构化评分与事实核对
信息完整性虚构事实、丢失约束、语义失真对照输入逐项检查
轻量化默认加载资源、上下文 Token、输出长度真实 Agent 运行数据
可用性离线、键盘、移动端、交互成功率浏览器自动化与人工抽检
兼容性不同 Agent 的规则遵循情况跨 Agent 同题评测
稳定性边界缺陷、回归失败、重复初始化问题固定种子压力测试与回归套件

禁止只用测试通过率代表产品质量。测试集是否覆盖真实任务、失败样本是否有代表性、评估是否独立，同样重要。

明确的非目标

  • 新增第八、第九种语义图类型。
  • 为普通 Markdown 回答增加页面外壳。
  • 大量动画、装饰卡片和无业务意义的交互。
  • 独立在线图表编辑器、账户系统或协作平台。
  • 绑定某个模型或 Coding Agent 的专有实现。
  • 仅为截图观感改变内容结构。
  • 把 HTML、SVG、JavaScript 细节重新塞进核心 Skill。

下一阶段建议交付清单

  • 当前版本已知回归全部收口，形成可信稳定基线。
  • 梳理并确定信息设计决策模型及反例。
  • 新增按需加载的决策参考文档，不显著增加核心 Skill 体积。
  • 建立 Markdown / HTML / Visualization 三类代表性任务集。
  • 完成新旧 Skill 的真实 Agent A/B，保留原始输出与评分。
  • 根据失败样本迭代规则，而不是凭主观继续增加规则。
  • 更新 Before / After 案例，证明信息理解成本确实下降。
  • 完成跨 Agent 与浏览器回归，再决定下一版本是否封版。

最终产品原则

GEN-UI 不是教 AI 如何生成漂亮的页面，而是教 AI 如何理解信息、组织知识、选择表达形式，并交付高可读性、高质量的信息成果。

无论最终交付的是一段 Markdown、一张表格、一幅架构图，还是一份交互式 HTML 文档，都必须服务于同一个目标：让复杂的信息变得清晰，让重要的知识更容易被理解，让有价值的内容更容易被使用。

UI 是手段，信息理解才是目的。
