# GEN-UI · 能力路由与加载边界

> vNext 规则：**默认 Markdown；按明确交付物逐层增强。** 本页解释内部路由，不是每次输出给读者的格式模板。

## 一、按照交付物选择

| 用户任务 | 最小输出 | 按需规则来源 | 不应自动做什么 |
| --- | --- | --- | --- |
| 普通解释、代码评审、规划或未指定格式的“报告” | Markdown | SKILL.md | 自动生成 HTML、伪按钮或固定工程总结 |
| 多方案同维度对比、步骤和证据评审 | Markdown 表格、步骤、风险矩阵 | 信息形状难判断时才读 information-design-decision.md | 无数据添加图表 |
| 明确要求仓库内离线静态 HTML 文档 | 可点击真实目录的内容型 HTML | html-report-essentials.md | 额外制造筛选、分页、弹窗、仪表盘 |
| 明确要求独立单文件 HTML、复杂交互或门户 | 具备必要功能的 HTML | html-report-contract.md 和要求的门户构建器 | 功能缩减为不可用空壳 |
| 架构分组、层次或归属需要可视化 | 分层容器、结构矩阵 | architecture-patterns.md | 编造调用关系和方向 |
| 真实的时序、ER、部署、泳道等专业关系图 | 语义图和文字说明 | semantic-diagram-model.md；若生成 HTML 再按需读取 HTML 合约 | 七种图画成相同箱线图 |
| 宿主明确支持 gen-ui-demo/v1 | 校验过的声明式 UI + Markdown 回退 | renderer-contract.md | 在纯文本宿主制造假交互 |

**优先级：用户明确指定格式 > 宿主实际支持的能力 > 信息形状。** 单说“架构”“分析”“报告”不能自动触发 HTML。未说明格式时使用 Markdown。

## 二、规范唯一归属

- SKILL.md：基础路由、阅读目标、准确性和检查边界。
- information-design-decision.md：结构选择、内容压缩与事实、建议、未验证区分。
- html-report-essentials.md：简单静态 HTML 的必要内容与离线交付。
- html-report-contract.md：高级 HTML、单文件、交互、离线资源和完整验收规范。
- architecture-patterns.md：分层、归属与架构关系表达。
- semantic-diagram-model.md：专业图类型、节点关系、模型输入和语义交互。
- renderer-contract.md：仅当宿主确实支持声明式 UI 才启用。

规则出现重复时，优先**链接唯一来源**，不复制整段实现细节。简化输出并不等于取消离线、安全或无障碍约束；只在用户实际需要高级功能时加载完整合约。

## 三、降级与证据边界

1. 宿主不能交互则退回 Markdown，保留可以阅读的结论和数据。
2. 未知状态机门槛、未确认的组件依赖、未运行的验收均应明确标注；不把建议写成已上线事实。
3. 没有真实数据或关系，就不用图表；优先让读者理解、比较和决定。
4. 用户要求不测试时，允许继续源码和文档整理，但要说明“未测试”，不得宣称验收通过。

本轮为 2026-11-13 文档与路由整理；未运行模型、浏览器和自动化测试。
