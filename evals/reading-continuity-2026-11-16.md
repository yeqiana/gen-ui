# GEN-UI：信息分层与多轮评审连续性专项验收

日期：2026-11-16。范围：纯 Markdown 信息组织、续评与风险边界；不包含 HTML 样式或运行时业务测试。

## 结论

- **轻量性达标**：`SKILL.md` 由 5,273 B 压缩至 5,099 B，低于现有 5 KiB 门槛；按需加载参考文件 `references/reading-layers.md` 为 5,055 B。无新框架、持久化台账或网络调用。
- 新增明确路由：多轮续评、**风险/收口判断**才按需读取 `reading-layers.md`；简单问答仍按 Markdown 最小结构，不默认输出报告/HTML。
- **证据分界**：已改代码 ≠ 已测试；缺少日志/用例 ≠ 已证实未实现；已知失败不等于根因已明；限定环境/期限接受风险不等于生产可放行。每轮关联同一议题 ID 的历史、增量和未决证据，避免重复整篇。
- **真实模型验收存在迭代过程，不能伪称一次即通过**：首轮出现两类误判，经参考文件加载路由和一致性边界修复后，专项复测消除了已观察到的两类问题。见下表。

这些案例均为**人为构造的回归材料**，不代表 QR01、StoryOS、签名系统或其他实际项目的运行事实。模型执行路径为 Windows 桌面用户会话的原生 Claude Code，由本地 Runner 启动，**未调用 OpenCodex 代理或 Codex 额度**。各案例提示词见 [固定测试集](review-continuity-cases.json)，原始模型事件日志保留在本地的非发布 `evals/artifacts/reading-continuity-2026-11-16/`。

为避免把测试脚本当作能力证据，单测只证明规则和样例结构存在；真实模型答复经过内容检查。第一次运行因 Windows PowerShell 重定向将中文 UTF-8 错解码，重新使用 Node 原样采集字节，方得到可人工审阅的中文输出；乱码轮次不参与质量结论。

**证据局限：** 这是少量定向案例，不构成任何模型/宿主的统计成功率。最后一次小范围修改仅扩大了风险/收口情境的按需加载条件；没有把四个案例在完全相同的最后字节版本下再次从头全量运行，因此不能宣称「末版 4/4 独立模型基准通过」。
