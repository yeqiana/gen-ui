# GEN-UI 正确授权后的未见题语义稳定性对照

日期：2026-11-16。**结论：本轮授权和运行链路稳定；GEN-UI 的自动触发可观测性优于前轮，但尚不足以证明语义质量具有普遍、显著优势。没有据此修改核心 Skill。**

## 1. 冻结与实验范围

- **Skill 冻结 Git SHA：** `d0d40769725740a380c399946e31af87cdf0753d`。核心 `SKILL.md` SHA-256 为 `ca978309b388b62c68e0bd54e2e04f9ec1dd7d0c1ed2a57522c24b7e4e11ee48`、大小 **5,099 B**；运行时已核对用户级安装文件与冻结版本一致。参考文件也按该提交冻结，执行期间未修改。
- **模型与执行：** 已登录的 Windows 桌面 Claude Code，实际模型标识 `claude-sonnet-5`，本地 Runner 四槽滚动并发，每次最多 7 回合，固定预算上限 USD 0.38。没有使用 OpenCodex 代理或 Codex 额度。
- **全新合成题库：** [5 个固定案例](semantic-fresh-cases-2026-11-16.json)，分别考察：接口验收中相同哈希不能证明会议引用来源；36 小时内部预发布批准不能扩大为对外 Beta；45/45 已测通过与 45/60 计划覆盖的区别；T1/T2/T3 跨轮“已改/待验证/已知失败”追踪；两三句话解释 Embedding 与向量索引。
- **每题 2 次 × 3 组 = 30 次全新会话：** 自然组不点名 Skill，显式组仅在提示词前加 `/gen-ui`，基线组使用同一自然提示但禁用 Claude Code 的 Slash Commands（因此不启用 Skills）。所有组使用 `user,project` 配置源以保留本机认证；自然/显式组只追加 GEN-UI 安装目录的 `--add-dir` 权限。基线与其他组的工具可用性不同，因此不是严格控制变量的因果研究。

## 2. 对照结果

| 指标 | 自然触发 | 显式 `/gen-ui` | 禁用 Skill |
| --- | ---: | ---: | ---: |
| 正常完成 | **10/10** | **10/10** | **10/10** |
| GEN-UI Skill 工具成功调用 | **6 次 / 6 次尝试** | 0 次独立工具事件 | 0 |
| 成功读取 GEN-UI 规则（总次数） | 3 | 2 | 0 |

| 输出长度中位数（去空白字符） | 1,109 | 1,139 | 1,263 |

**触发口径：** 在原始事件中，GEN-UI 工具调用必须匹配 `input.skill === "gen-ui"`，且对应的工具返回非错误。自然组 6 次调用均成功，未混入其他 Skill。自然组另有 3 次参考文件成功读取，其中 2 次与工具调用发生在同一会话，因此有至少 **7/10 次自然组会话出现可观测的 GEN-UI 激活证据**。显式 `/gen-ui` 可能由客户端自行展开，不产生独立工具记录；它的 0 次工具调用并非“未执行 Skill”的证明。仅以成功 `Read` 计数会漏掉工具激活和内置斜杠展开。

**自动初筛边界：** 检查的是预设数字、关键词、结论位置和少数显式越界表述，不等于语义正确率。初筛标红的 3 份回答人工复核后均属于词形/表达顺序漏检，不能算真实的 3 次回答失败；本轮**保留原初筛结果**，没有为了把分数变绿而调整主评分门槛。

## 3. 人工复核与真实错误

- **来源关系：** 各组回答整体能够指出 X/Y 哈希一致不代表口头结论属于同一运行，也没有用更好的“20/20”口头值覆盖“19/20”日志记录。个别答复会加入“备份完整性”等额外推断；应避免把单次哈希核对写成长期时间段的完整保管链证明。
- **授权边界：** 原则上区分了 I7 的 36 小时 / 内部 / 预发布批准与对外 Beta 前的修复门禁；A4 的代码合并也未被当作负向用例已通过或生产已被利用。
- **覆盖率：** 6 份回答均能写出已测 **45/45 = 100%** 与执行覆盖率 **45/60 = 75%** 的不同口径，并说明 15 份未测（5 排期、10 未知）不能直接记为失败。
- **真实算术推断错误：** 基线组 `partial-coverage-baseline-r1` 将“45/60 = 75%”错误写为“假设剩余 15 份全过时的上限”。该上限实际上是 60/60 = 100%；75% 是**当前执行覆盖率**。这一错误没有被预设词项筛查捕获。事后增加了`flagsWrongCoverageUpperBound` 独立诊断及单测，**没有回写前面 9/10、10/10、8/10 的主评分**。
- **多轮与简答：** T2 缺代码状态时没有必要写成“已实现/未实现”，T3 的 2/5 失败应与根因未明并列；简单 RAG 解释六份均保持短 Markdown，没有自动升级为 HTML、目录或表格。

**人工评阅不是独立盲审**：基于固定提示词和原始答复进行人工检查，只可列举已发现的具体错误与条件，不能声称“其余 29 份均达到所有语义标准”或把差异作为统计显著性结论。每题只有两次重复，样本不足且部分任务本来就比较容易。

## 4. 结果与后续决定

本轮**不改 `SKILL.md` 和 `references/reading-layers.md`**。没有发现证据充分、跨样本重复的 GEN-UI 核心机制缺陷需要继续增加提示词。新增长期可复用的零依赖离线筛查脚本与语义案例；该评分脚本只用于诊断，不取代真实评审、外部引用验证或业务系统测试。

下一步更有价值的是：将 GEN-UI 的实际使用场景引入独立盲审和未见的工程文档，以来源可追溯、未决证据保留、决策一致性以及**阅读效率**为目标，而不是继续针对同一组题目调高自动通过率。未来若调整 Skill，应在另一个隔离测试集上测回归，再发布。
