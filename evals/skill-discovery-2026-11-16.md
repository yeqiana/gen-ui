# GEN-UI 显式调用与自然语言触发：独立重复评测

日期：2026-11-16。**结论：权限问题已定位并找到低成本缓解方式；模型自动发现率与内容改善尚不能宣称稳定达标。** 核心 Skill 文件维持原样，不增加工具框架。

## 一、实验设置及冻结信息

- 冻结提交（本地）：`51afac426bc67ec16c6b845c268d6bd13a51691a`；与当时 GitHub `2498e43f5ce9e49b92dcada93c8d16ea339f8b1c` 具有**相同 Git Tree SHA**，其内容版次一致。
- 固定 GEN-UI `SKILL.md`（SHA-256 `ca978309b388b62c68e0bd54e2e04f9ec1dd7d0c1ed2a57522c24b7e4e11ee48`）、阅读层参考、模型 `claude-sonnet-5`、每次最多 8 回合。模型在 Windows 桌面 Claude Code 正常登录环境运行，没有使用 OpenCodex 代理或 Codex 额度。
- 输入：原有 4 个冻结问题各重复 3 次；新增“哈希同一性 ≠ 口头摘要来源”和“48 小时内部沙盒授权 ≠ 生产已放行”2 个合成问题，各重复 2 次，**合计 32 次**。
- 两组都在各自的全新工作区安装同一版项目 Skill。自然组使用原题，显式组只在提示词前加 `/gen-ui `。这是“显式使用方式”对比，并不是纯粹因果的内容对照。
- Claude Code 使用 `--setting-sources user,project`，会同时暴露用户级的其他 Skills 和设置。纯项目隔离 `--setting-sources project` 的探针因无法读取桌面账号登录状态而退出，未计入模型有效样本。每次原始事件与执行结果仍保存在本机 `evals/artifacts/genui-discovery-2026-11-16/`，不提交公开仓库。

## 二、32 次实际结果

| 项目 | 自然语言 | 显式 `/gen-ui` |
| --- | ---: | ---: |
| 模型正常结束 | **16/16** | **16/16** |
| 题目里明确包含 `/gen-ui` | 0/16 | 16/16 |
| `system.init` 列出 `gen-ui` 可用 | 16/16 | 16/16 |
| **实际成功读取 GEN-UI 规则文件**（至少一次） | **1/16** | **5/16** |
| 成功读取规则文件的次数 | 2 | 6 |
| 规则读取被权限拒绝的次数 | 0 | **7** |
| 独立 `Skill` 工具调用中点名 `gen-ui` | 0 | 0 |
| 原有四题的自动规则初筛通过 | **7/12** | **11/12** |
| 输出长度中位数（去空白字符） | 782 | 794 |

**统计口径**：读取成功必须能在原始 JSONL 中匹配 `Read` 调用及其对应的非错误 `tool_result`；读取被拒绝不计成功。工具实际调用必须检查 `input.skill === "gen-ui"`，不能把其他 Skill 算进去。显式斜杠命令可能由客户端直接展开且不留独立 Skill 工具事件，因此本表的文件读取成功次数不是内部“Skill 已激活”的全量统计。

原有四题 `7/12` 与 `11/12` 是**自动规则初筛**，不等于完整语义正确率。人工抽查发现有真实的“R2 缺验证证据被说成未实现”，也有把正确内容判错的正则漏检（例如答复将收口结论放在较后位置，或把“演示不是验证”换了一种说法）。新增加的两个独立合成题共 8 份答复，经逐份检查，均保留了来源关系与授权范围的主要限制；但评阅不是盲审，样本仍少，不能据此宣布稳定解决来源误推断。自动筛选词形规则在查看部分输出后进行了修订，结果仅限工程定位。

## 三、发现的关键根因与权限复测

部分显式调用试图读取 `~/.claude/skills/gen-ui/references/` 下的规则，但该目录位于 Claude Code 任务工作区之外；未授权时 `Read` 返回权限拒绝，模型可能就此回答、改用工作区副本或再次重试。

用 Claude Code 已支持的 `--add-dir` 参数，**只允许本次会话读取用户级 GEN-UI Skill 安装目录**，针对三份原来存在目录读取拒绝的显式案例复测：

| 案例 | 原始调用 | 定向 `--add-dir` 后 |
| --- | --- | --- |
| R1/R2/R3 续评 | 用户级规则读取被拒绝 | 规则读取成功，无权限拒绝；R2 不再被断言“未实现” |
| QR01 冲突证据 | 用户级规则读取被拒绝 | 规则读取成功，无权限拒绝 |
| 48 小时沙盒范围 | 曾发生用户级规则读取拒绝 | 规则读取成功，无权限拒绝 |

**3/3 权限复测达成“读取成功且不再被拒绝”**，但它不是用户环境中长期稳定性的证明，也没有证明语义内容必然变好。例如 QR01 的新回答仍把哈希同一性过度解释成口头摘要的来源关系。详见 [Claude Code 最小权限使用方式](../docs/claude-code-skill-loading.md)。

## 四、最小修复

1. 修复上一轮评分器：过去 `3/12` 是“任意 Skill 工具调用”，其中 1 次其实是其他代码协作 Skill。严格核对 GEN-UI 调用实际是 **2/12**。已在 [上一轮报告](review-continuity-stability-2026-11-16.md) 写入勘误，原始回答和记录不改动。
2. 新增 `evals/score-skill-discovery.mjs`，把 `Skill` 调用、成功的 `Read`、权限拒绝以及 `/gen-ui` 明确请求分开统计；加单测验证其他 Skill 不能混算、拒绝读取不算成功。
3. `references/reading-layers.md` 新增很短的来源链和环境授权边界；但这项调整发生在冻结的 32 次运行**之后**，不能把原始测量当作新规则的通过证明。
4. 提供 Windows 本地 `--add-dir` 最小权限指引。只允许读取 GEN-UI 自己的安装目录，不扩大为整个用户主目录，不新增常驻进程或依赖，**`SKILL.md` 仍为 5,099 B**。

## 五、后续验收方向

- 将“显式用户选择”“可用列表列出 Skill”“确切工具调用”“成功读取规则”分开统计，避免只用一个“触发成功率”掩盖权限和日志不可观察的差异。
- 先在更隔离、具有有效账号认证的环境里测自动发现；不能在混有用户级同名 Skill、其他 Skills 的条件下对某一份项目 `SKILL.md` 的发现效果作严格因果判断。
- 未来评分应使用独立未见过的问题和盲审，尤其检验来源证明链、风险授权范围、默认简洁及跨轮结论一致性，不能为了本组测试反复调整正则或提示词。
