# GEN-UI P1 · 跨项目语义风险提示收口

日期：2026-11-18。结论：**增加轻量级、只提示不判决的关系风险标记；两份原始真实模型候选和冻结 Git 来源均未修改。P1 独立语义验收仍未通过。**

## 1. 解决的问题与边界

此前两份 Claude CLI 真实模型候选均通过来源结构校验、Chrome 6/6 场景，但 61 项 AI 辅助来源审查中有 12 项不确定、2 项不支持。原审查器能够提示单纯引用章节标题的模块，却不会单独标记以下关系：

- **异常回退被画成依赖**：原文描述“不支持时报告”“不能路由时改为单 Agent”，不自然等同于两模块静态 `depends`。
- **并行检查被画成串行流程**：原文要求同时运行多项断言，不应未经核查就表示为 `flow` 顺序箭头。
- **自然语言条件的控制约束不完整**：原文 `Reader invalid ⇒ Reconcile 不得 healthy` 是受条件约束的规则，不应仅靠 `controls` 关系就称其条件已保真。

此次仅修改 `evals/semantic-review.mjs` 中的**审查优先级提示**，不增加服务、依赖、模型调用，也不修改核心 `SKILL.md`、来源结构评分器和渲染器。提示根据已经验证属于冻结 Git 的引用行产生，来源不合法时不会凭空给风险作正面解释。

## 2. 新的审查风险标记

| 标记 | 触发条件 | 判决边界 |
| --- | --- | --- |
| `FALLBACK_POLICY_LABELED_DEPENDS` | `depends` 的原文同时描述不可用/失败和改为、降级、报告等处置 | **只提示**关系可能是异常处置而非静态依赖 |
| `PARALLEL_OPERATION_LABELED_FLOW` | `flow` 的原文包含“同时运行”“并行执行”等并行含义 | **只提示**并行操作和顺序转移不能直接互换 |
| `CONDITIONAL_PROSE_NEEDS_REVIEW` | `controls` 的自然语言来源有条件和否定约束，而候选没有条件标签 | **只提示**原文条件可能丢失；不自动填 `condition` |
| `HEADING_ONLY_MODULE_EVIDENCE` | 既有规则：模块仅引用 Markdown 标题 | 保留旧提示，不能把章节存在当作真实部署证据 |

风险标记既不能单独否决候选，也不能将 `STRUCTURAL_PASS_SEMANTIC_UNVERIFIED` 升级成完整语义通过。自然语言里的条件与 Mermaid 的明确 Yes/No 箭头证据不同；现有来源结构规则对没有原文 Mermaid 条件箭头时自填 `condition` 仍会阻断，**本轮不改变此规则或暗中修复旧模型结果**。

## 3. 冻结候选实测（不消耗新模型额度）

来源为 `unseen-panorama-2026-11-17.json` 中冻结的 Agent Lead 和 Distributed Systems Audit Git 提交，以及 2026-11-18 前轮已经执行并留存 SHA-256 的原始真实模型候选。通过现有来源还原与审查包生成器重新计算：

| 项目 | 审查条目 | 此前标题风险 | 本轮新增关系风险 | 当前来源结构校验 |
| --- | ---: | ---: | ---: | --- |
| Agent Lead | 30 | 0 | **2**：`relation:1`、`relation:2` 异常回退/依赖混淆 | 0 问题，通过 |
| Distributed Systems Audit | 31 | 10 | **2**：`relation:2` 自然语言条件、`relation:3` 并行/串行混淆 | 0 问题，通过 |
| 合计 | **61** | **10** | **4** | 两份均 `STRUCTURAL_PASS_SEMANTIC_UNVERIFIED` |

这 4 条新增提示与前轮 AI 审查定位的 4 条有争议关系逐一对应。对普通顺序箭头、有明确原文依赖、无效引用和明确保留条件的反例进行测试，避免规则泛化为无根据的自动断言。

### 审查记录与历史一致性

- 为**新的风险提示规则**创建了两个全新审查包，而不是覆盖前轮审查记录：Agent Lead 30 项、Distributed Systems Audit 31 项，新的审查草稿目前 **61 项均为 `pending`**。
- 相比旧包，两个新包的全部**模块/关系陈述与冻结引文逐项完全相同**，仅四条关系增加了审查提示。旧候选、冻结来源、已执行的模型日志和旧 47/12/2 AI 初核记录均保持不变。
- 审查包内容签名因此发生变化；旧审查决定不可直接冒充新版包审查结果。新包还需重新确认并签署，当前状态 `PENDING_SEMANTIC_REVIEW`，**不是 61 项语义合格**。
- 既有报告中 47 项 AI 初核支持、12 项不确定、2 项不支持只是**历史人工辅助判定结果**，不构成真人独立语义认证。

### 风险确认门禁

审查草稿现在为带有风险标记的条目增加 `acknowledgedRisks: []`。若审查者将此类条目标为 `supported`，必须逐一确认各项风险，否则 `evaluateReview` 返回 **`BLOCKED_RISK_UNACKNOWLEDGED`**；未知或重复的风险确认也会被拒绝。标记为 `unclear` 或 `unsupported` 的条目不要求强行确认，原有语义异议阻断仍优先。

风险确认只是可审计的**审查者自述动作**，不是证据正确的证明；全部确认后的最高状态仍是 `ATTESTED_NOT_INDEPENDENTLY_VERIFIED`。当前两份真实候选存在异议，不会因增加确认字段就变成语义通过。

## 4. 验证与后续

本轮新增两项跨项目负向单元测试：一项覆盖三种关系风险提示及合法依赖、普通 Mermaid `flow`、非法来源和有明确条件时的无提示对照；另一项验证风险未确认时阻断 `supported`、确认全部风险后仍仅为自述审核，以及伪造风险标记时拒绝。专项与完整 Node 测试均通过。审查工具不调用 LLM，原始 JSONL、完整候选和逐项审查包均只保存在本机公开仓库外，不向 GitHub 上传。

本地完整 Skill/Node 回归 **183/183 通过**。一次独立的本地 Chrome 全套脚本运行中，报告、导航、文档、排版、移动端、折叠阅读及 HTML02/03/04 **全部通过**；另一次并行验证中 HTML03 曾出现 Chrome CDP 进程启动异常，随后单独复测通过。保留该环境波动记录，不将一次启动失败误写为代码缺陷，也不删除失败证据；远端 CI 仍需独立验证。

**下一步建议**：让独立审查者优先核查已标记的 14 项（10 个标题风险、4 条关系风险），明确哪些可以保留为“文档能力”，哪些必须改变关系类型或从架构中删去；与 PlanShip 原始流程图重复节点 `A` 和 `V -- No --> X` 未解释分支的源头修正分开处理。没有新的冻结源和独立语义结论前，P1 仍保持未验收通过。
