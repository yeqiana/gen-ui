# GEN-UI 四案例 × 三次重复：Skill 与非 Skill 对照评测

日期：2026-11-16。结论：**24/24 会话完成，但没有足够证据认定 GEN-UI 带来稳定、显著的语义质量或篇幅改进。** 当前更大的问题是 Skill 自动触发率偏低，以及无论是否调用 Skill，复杂证据来源都可能被过度推断。

## 1. 冻结对象与实验方法

- **固定 Git 提交：** `6676adec6803fe3bfa4d285634695b079c8e0d1f`。该提交里的 `SKILL.md`、`references/reading-layers.md`、`references/information-design-decision.md` 和 [四个固定提示词](review-continuity-cases.json) 均在运行前单独取样并记录 SHA-256；执行中不修改 Skill。
- **模型/执行：** Windows 本地 Runner，桌面用户会话中的原生 Claude Code，实际模型标识 `claude-sonnet-5`；不使用 OpenCodex 代理或 Codex 额度。每组最长 8 回合、单次模型预算上限 USD 0.48，4 槽滚动并发。
- **设计：** 四个案例各运行 3 次 Skill 组 + 3 次对照组，总计 **24 个全新会话**。每个案例的用户提示词逐字相同，并记录提示词哈希；两组各 12 次。
- **Skill 组：** 工作区安装冻结版 `gen-ui` Skill。**对照组：** 工作区不安装项目 Skill，禁用 `Skill` 和 `Read` 工具。两组均禁止不相关的终端写入、WebFetch/WebSearch。该控制方式存在工具可用性差异、全局用户 Skill 元数据可能可见的局限，**不是理想双盲实验**。
- 原始 `events.jsonl`、提示词、执行日志、各次 `answer.md` 和 `scored.json` 位于本地 `evals/artifacts/reading-stability-2026-11-16/`；原始执行事件包含系统本地路径等信息，**不提交公开 GitHub**。

**自动初筛的含义：** 由 `evals/score-review-continuity.mjs` 检查判断位置、原始指标保留、少数显式风险边界和长度。**不是语义正确率或事实准确率**；保留 `11/12` 并不代表正确解释了它的证据地位。词项保留 60/60 仅说明预设文字及允许的少量同义形式出现。

**触发率勘误（本轮复核）：** 初版评分器把任意 `Skill` 工具调用计为 GEN-UI，故原记录中的 3/12 混入一次 `ai-coding-collaboration`。按 `input.skill === "gen-ui"` 核对原始 24 份事件，GEN-UI 工具调用实际为 **2/12**；此外“读取参考文件”不等同于显式调用 Skill 工具。自动评分脚本已纠正，历史模型输出未改动。\n\n评分器初版曾得到 **9/12 vs 8/12**；人工检查发现“不能结束”未被识别为不能收口、表格中的“没有新的识别测试”被漏检等正则误报，补测试后改为 **11/12 vs 9/12**。**评分规则在看到结果后调整过**，所以修订后的数字仅用于工程诊断，不能伪装成预注册、未经调整的科学统计结果。

## 3. 人工复核发现的真实问题

1. **R2 状态过度断言：** Skill 组第 1 次与对照组第 1、3 次，把“没有对账日志和验收用例”直接判成“未实现”，与输入证据不匹配。Skill 组该次虽调用了 `Skill`，但未继续读取续评规则；这不能算 GEN-UI 可靠阻止错误的证据。
2. **QR01 来源过度推断（两组均出现）：** 多份回答把“文件 SHA-256 一致”写成“第 1 轮口头摘要肯定引用第 2 轮的同一份原始日志”。输入只给出了日志数字及文件核对一致，并没有提供口头摘要的实际来源；哈希不能单独证明那一层关联。这类问题**不会被词项保留率发现**。
3. **N1 放行条件的表述：** 个别生成内容将“正式生产前仍需修复”弱化为“有修复排期/结论”，或者写成“生产已经受到影响”；原始材料只说当前影响内部试用，不能凭空推断生产实际运行状态。
4. **阅读密度并非稳定提升：** Skill 组在 R1 某次报告末尾重复完整摘要；而风险授权和冲突证据两个题目的中位长度反而比对照组更长。整体中位数略短，但整体均值更长，不能推断稳定减少冗余。
5. **自动加载不足：** 严格按工具参数检查，12 次启用条件下只有 **2 次调用 `gen-ui`**，另 1 次调用了其他代码协作 Skill；2 次尝试读取 `reading-layers.md`。这次“启用组”不是“12 次都执行了 Skill 规则”的效果测试；两组差异也可能受随机波动、工具策略和模型自身能力影响。

## 4. 当前判断与下一步

**当前结论：暂不认定信息设计增益已经稳定。** 核心 Skill 保持原样，避免拿 24 个小样本反复调提示词、再用同一套测试把结果调绿。

更有价值的下一轮是单独冻结**明确点名 Skill vs 自然语言自动发现**两种触发方式，先测实际加载率，再分别评估内容质量；另外在新的题目上增加“来源推断越界”“有范围授权和实际生效状态不能混淆”两种**语义评审用例**。需要独立提示词与盲审，不能用本次四题直接做最终质量认证。
