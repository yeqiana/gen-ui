# GEN-UI 正文标题断行根因与实机回归（2026-11-17）

**结论：已复现并修复本轮覆盖的孤字/短尾断行。** 旧代码并非标题 HTML 被插入了人工 `<br>`；主要问题是 375px 手机、768px 展开导航等窄阅读列中的标题使用普通 `text-wrap:wrap`，Chrome 会将末尾一至四个字挤到下一行。旧浏览器验收只查溢出/列宽，未查真实末行字数。

## 实际复现

- 基线：7 个报告/中英文示例、375/768/1024/1440px 和部分折叠状态共 **658 条标题渲染记录，13 处孤字/短尾**，原始浏览器记录仅留本机 `evals/artifacts/title-wrap-2026-11-17/baseline-flags.json`。
- 典型：`AI 内容生产平台项目分析报告` 最后一行仅一个“告”；`产品架构全景图 · 架构设计 · 目标产品能力蓝图` 最后仅“图”；报告 H3 `问题排查：症状 → 假设 → 证据 → 下一步` 最后仅“步”。
- 源码核对：四中文案例没有标题中的转义换行串 `\\n` 或 `&#x20;`；**问题属于浏览器排版，不是无根据的 Markdown 源文本错误**。

## 修复路径与保持的限制

1. `demo/documents/assets/document.css`：正文 H1–H4 保持父列 `width:100%`，只给标题启用 `text-wrap:balance`；正文段落仍按真实阅读列宽 `wrap`。
2. `demo/report.css`：同样控制报告正文 H1–H4，避免报告里的长 H3 出现单字末行。
3. `assets/typography.css`：修复模型生成离线 HTML 的**另一套 CSS 入口**，防止只修四个示例、新生成的报告仍出错；严禁把标题 `max-width` 设成 75% 之类的窄列。
4. `scripts/accept-html-delivery.mjs`：浏览器交付门禁增加中文标题末行字数检查、父列宽占用检查和真实字符行盒统计。仍严格拒绝人为 `<br>`、裁切、缺失有效导航。
5. `references/typography.md`：只补充一段按需排版说明，不改变 `SKILL.md` 的轻量入口；对段落禁止 `balance/pretty` 的原有规则保持不变。

旧测试曾将 *`balance` 配合 `max-width:75%`* 判为过早断行。该缺陷来自**人为缩窄标题实际占用宽度**，不是允许标题在完整列宽里均衡断行。新版验收允许完整列宽的均衡标题，但继续阻断缩窄列宽，不能用减少真实内容宽度来制造所谓的整齐标题。

## 新增不可假绿的浏览器门禁

- 新测试：`tests/chrome-heading-break-smoke.mjs` 使用 Chrome `Range` **逐字符获取实际渲染行框**，不靠字符串长度猜换行。
- 现在覆盖中文和英文报告、四中文技术案例、四英文技术案例、两份 generated-typography 夹具，共 **12 页**。
- 视口：375 / 768 / 1024 / 1440px；含 **36 个已折叠导航的真实视图**；检查孤字/短尾（长标题末行 ≤4 字）、超窄标题容器、裁切、人工 `<br>`。
- 最新结果：**917 条标题渲染记录，25 条发生正常多行排版，0 处异常**。基线的七个页面也包含在本轮范围内。
- 已有 `tests/chrome-typography-smoke.mjs` 继续验正文段落的 `text-wrap:wrap`、真实行高及列宽；`tests/chrome-documents-smoke.mjs` 继续验各页面及三种宽度；`tests/chrome-report-smoke.mjs` 验报告交互与弹窗。

## 仍需区别的验收条件

在**仅有三个目录条目**的生成 Typography 夹具上，`accept-html-delivery.mjs` 的 46 项实测为 **44 项通过**；全部标题验收项均通过，另两项“长目录需要有导航内滚动”不通过（该夹具目录不够长），因此不能声称该夹具完整 HTML 交付验收已通过。长目录行为由其独立导航/浏览器用例验证，不能借标题修复隐去真实失败。

本轮不是字形级跨浏览器全平台保证：Chromium/Chrome 是实际验收宿主；打印与其他渲染内核仍需分别实测。
