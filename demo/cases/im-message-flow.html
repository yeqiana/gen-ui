SYSTEM DESIGN / MESSAGE DELIVERY

即时通信：群消息受理与可靠投递

把“是否允许发送”与“如何把消息送达”拆成两段可审计流程：受理时冻结授权边界，持久化后再异步分发。

群成员授权快照消息持久化 + OutboxMQ 异步投递ACK / 重试 / 幂等

群消息受理与投递链路

客户端发送请求 / client message id
IM Core参数校验 / 受理入口
关系授权服务成员关系 / 原子快照
消息存储消息记录 / Outbox
消息队列异步事件 / 消费重试
收件人在线推送 / 离线补拉
关键边界：授权快照在受理时确定本次收件人集合。后续群成员变化不应让同一条已受理消息在不同重试批次中悄悄改变收件范围。

受理阶段 · 授权快照

  • 关系服务是成员、角色、禁言等关系事实的权威来源。
  • IM 获取一次原子授权结果，并固定本次收件人集合。
  • 缓存未命中不等于“不是成员”；授权服务不可用与明确拒绝必须区分。
  • 消息记录、会话更新和异步事件应共享同一受理边界。

投递阶段 · 可靠性

  • 先持久化消息和待投递事件，再由消费者异步分发。
  • 使用消息唯一标识实现重复消费幂等。
  • 失败重试有上限，超过阈值进入隔离队列供排查。
  • ACK、离线补拉和已读游标按明确顺序推进。

设计关注点

01
授权一致性

成员关系快照必须来自权威服务，不能用缓存 Miss 代替业务拒绝。

02
事务与事件边界

消息写入与 Outbox 事件在同一受控事务中提交，避免“消息已存但事件丢失”。

03
重复与乱序

消费者按消息标识去重，状态更新携带单调版本，防止旧事件覆盖新状态。

04
可观测与恢复

记录积压、失败原因、重试次数、ACK 延迟和隔离队列，形成可复跑证据。
