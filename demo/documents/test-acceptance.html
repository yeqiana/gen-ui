ENGINEERING DOCUMENT / SANITIZED CASE

测试与验收方案 · 异步任务可靠性专项

围绕任务状态一致性、重复投递、租约过期、进程崩溃与断点恢复设计可重复的测试用例，并定义验收所需的原始证据。

验收原则

只认可可复现的测试证据。状态正确性、唯一执行权、消息幂等和故障恢复属于 P0 门禁；性能指标必须在目标环境测量后再确定，示例参数不能冒充实测结果。

一、测试目标与策略

测试重点是验证任务编排的正确性与故障恢复能力，而不是只验证“正常路径能跑通”。测试必须覆盖状态机、消息重复、执行权竞争、进程中断、恢复对账、权限隔离和可观测性。

测试层级
层级验证对象主要方式交付证据
单元测试状态迁移、错误分类、退避策略、幂等判断固定输入、边界值和属性测试测试报告与覆盖率
集成测试数据库事务、Outbox、MQ、Worker容器化依赖、消息重放事件链路与数据快照
故障注入租约过期、进程崩溃、网络超时、ACK 丢失定点终止、延迟、断网、重复投递故障前后状态与恢复记录
并发测试同一任务竞争领取与提交多 Worker 并发执行token 变化与唯一有效写入证明
性能测试排队、吞吐、数据库扫描与恢复耗时逐级增加并发、持续压测原始指标、环境配置和瓶颈分析

二、环境、数据与前置条件

  • 使用隔离测试数据库、独立消息队列和模拟模型服务，禁止向真实用户或生产模型账户发送测试内容。
  • 准备固定 Run、Task、Attempt、Event 和 Artifact 样本；每轮测试记录数据集版本与输入摘要。
  • 测试 Worker 支持可控暂停、退出、延迟返回和网络错误注入。
  • 统一采集服务日志、数据库快照、消息 ID、Trace ID 和时间戳，保证证据可以关联。

每次故障注入应保留结构化证据，例如：

{
  "caseId": "TC-003",
  "runId": "RUN-DEMO-001",
  "taskId": "TASK-DEMO-001",
  "oldToken": 7,
  "newToken": 8,
  "expectedOldOwnerRowsAffected": 0
}

五、关键故障注入验证

旧执行者问题是分布式任务系统最重要的边界之一。测试必须刻意制造“旧 Worker 暂停、租约过期、新 Worker 接管、旧 Worker 恢复”的时序，而不是只测试正常的锁竞争。

Fencing Token 防止旧执行者覆盖结果
100%

图 1：Worker A 使用旧 token=7 回写时必须被数据库拒绝；Worker B 使用新 token=8 的结果保持有效。

建议故障注入步骤

  1. 启动 Worker A，领取 Task 并记录 token=7、Attempt A。
  2. 暂停 A 的执行线程或隔离网络，使其无法续租但保留进程。
  3. 等待租约过期，由恢复器确认接管条件后让 Worker B 领取，token 变为 8。
  4. 让 B 完成并提交成功结果，保存数据库快照。
  5. 恢复 A，让它提交旧结果；断言更新影响行数为 0，Task 结果仍属于 B。
  6. 检查 Event / Trace 中存在 stale-owner 证据，且没有第二个成功终态。

六、性能与稳定性测试

性能测试先验证功能正确，再逐步增加并发。压测结果必须同时记录环境规格、数据库配置、队列参数、模型模拟延迟、数据规模和测试脚本版本，不能只提供一个吞吐数字。

建议的测试阶梯（参数需评审后确认）
阶段并发任务持续时间观察重点
基线1010 分钟状态正确性、单任务延迟和基础资源占用
常规负载5030 分钟队列等待、Worker 利用率、数据库连接池
峰值模拟10015 分钟背压、限流、超时、Outbox 积压变化
恢复压力50 + 故障注入按故障窗口执行恢复扫描耗时、重复消息、状态收敛时间
阈值尚待确定

上表是测试阶梯示例，不是系统已达到的性能。P95/P99、最大积压、恢复时限和资源阈值应依据业务 SLA 与目标环境压测基线制定。

七、安全与数据正确性检查

  • 跨租户 Run、Task、Artifact 访问必须返回拒绝，不得通过猜测 ID 访问其他数据。
  • 取消、重试、补偿等管理操作必须鉴权并写审计事件。
  • 模型密钥、用户输入、产物 URL 中的签名参数不得进入普通日志。
  • 重复提交相同业务幂等键时返回既有运行结果，不创建第二条业务流程。
  • Artifact checksum 与元信息一致；过期产物清理不得删除仍被 Run 引用的文件。

八、验收门禁与证据要求

验收标准
门禁必须提供的证据通过条件
状态正确性状态迁移测试记录、数据库前后快照不存在非法迁移和终态覆盖
执行权唯一双 Worker 故障注入日志、token 变化旧 token 写入被拒绝
消息可靠性Outbox 记录、MQ 消息 ID、消费幂等记录重复投递不产生重复副作用

性能稳定性环境配置、原始指标、压测报告达到评审确认的 SLA 阈值

验收前检查清单

  • ⏳ P0 用例全部执行并附原始日志。
  • ⏳ 关键故障注入至少重复执行三轮，结果一致。
  • ⏳ 测试数据、代码版本、配置版本和脚本版本可追溯。
  • ⏳ 所有失败用例均有缺陷单、风险接受记录或修复复测证据。
  • ⏳ 灰度和回滚演练由实际值班角色完成。
